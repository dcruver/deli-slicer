# deli

CLI-first slicer front end for 3D printing. Python, managed with `uv` (src layout, package `deli`). Licensed AGPL-3.0-only because it links PrusaSlicer's `libslic3r`.

## What it is

- `deli` runs inside the user's shell: no REPL or TUI of its own. Each subcommand edits project state and exits.
- A print job is a `deli.toml` in the current directory: parts, their transforms, the chosen profiles, and only the settings overridden from those profiles.
- Slicing is done in-process by PrusaSlicer's `libslic3r`, linked into a Python extension module. No slicer application has to be installed.
- Profiles are PrusaSlicer INI. Orca JSON profiles are converted to INI by deli; the first target is the Elegoo Centauri Carbon.
- `deli load printer|filament|process <source>` copies a PrusaSlicer INI file, from an `https://` or `file://` URL or a path, into the per-user library in `~/.config/deli`. The network is used only to fetch profiles (this, and Orca's presets from GitHub) and to talk to printers (`DESIGN.md`). It leaves out connection settings (`print_host`, `printhost_*`); a printer's address lives in the config file instead.
- `deli import orca printer|process|filament "<Orca name>"` converts a preset from OrcaSlicer's repository on GitHub at the release `orca_install.ORCA_REF` (the one `PRINTERS.md` was made from; the wheel workflow's `ORCA_REF` must match, a test checks), `--ref` another, or with `--local` (or `--orca DIR`) from the OrcaSlicer installed on this machine, the user's own presets included (`src/deli/orca_install.py` finds the presets, `src/deli/orca.py` converts) into the library, or to a file with `-o`. A release's files are kept in `$XDG_CACHE_HOME/deli/orca/<ref>/`; shell completion reads only those, never the network. A printer brings Orca's default process and filament for it (`--printer-only` not), made the config's defaults where it has none; one that differs from a library entry of the same name, converted for another printer, is stored under a name with the printer's, so prints relying on the first keep working. `deli vendor [vendor|printer]` lists Orca's vendors, a vendor's printers, or the printers a name is part of. `deli printer|filament|process` without a name lists, without saying where each lives, the printer's vendor's printers or the filaments and processes made for the print's printer (Orca's shared filament library is counted, not read: hundreds of files), with the library's; Orca's are shown by Orca's names (`_list_kind`). The taxonomy the user wants: vendor, then printer, then filament and process for that printer (Orca ties processes to printers, not filaments). Test presets live in `tests/data/orca/`; `tests/conftest.py` stops any test from fetching from GitHub, and those that need it serve a fake (`github` in `tests/test_import.py`).
- Shared profiles are kept in `profiles/{printers,processes,filaments}/`, one PrusaSlicer INI file per printer, process or filament (Elegoo Centauri Carbon 0.6, Bambu Lab P1S 0.4); `tests/test_profiles.py` checks that each loads completely and that each printer's trio slices.
- `deli printer <name>`, `deli filament <name>` and `deli process <name>` each choose one for the print in the current directory and record its name and a hash of its settings in `deli.toml`: from the library by its name or a part only one has, or else one of Orca's presets found by `orca_install` (`_from_library_or_orca` in `cli.py`), imported into the library as it is chosen; a printer brings Orca's default process and filament, a process or filament is converted for the print's printer. When a print's printer changes, its filament and process change to the new printer's config defaults, naming what they were (`_follow_printer`); without defaults they stay, with a warning. A converted process or filament records the Orca printer it was made for (`# for:` in its file, `library.made_for`); choosing one made for another printer converts it again for the print's printer, kept beside it as `<name>-<printer>` (`_for_this_printer`); one without the line (loaded, older, or edited) is used as it is. The library is kept, not converted afresh each time, so a deli or Orca upgrade never changes a printer under a print; `deli import` re-converts on request. `deli.toml` is edited with `tomlkit` so hand-written comments survive. With `--default` they write the user's config instead and leave the print alone: `deli printer X --default` sets the config's `printer`, and `deli filament|process Y --default` sets `printers.<printer>.filament|process` for the print's printer or the default one.
- `deli add <file> [--count N]` adds a model to the print as a `[[part]]` table in `deli.toml`, after the engine has read it; adding it again adds copies. `deli remove <part> [--count N]` takes it, or some copies, out. A part is named by its file, with or without the extension.
- `deli set <setting> <value>` records a setting the print changes in `[settings]` in `deli.toml`, after the engine has checked it together with the chosen profiles; `deli unset <setting>` removes it. `src/deli/settings.py` holds the short names (`infill` for `fill_density`). Two settings are deli's own, not PrusaSlicer's (`library.OWN`): `print_flow_ratio`, Orca's print-level flow, kept in a process, which `settings.for_engine` (every path to the engine goes through it) multiplies the filament's `extrusion_multiplier` by; and `gcode_footer`, kept in a printer, comment lines that `slice` adds to the figures the G-code closes with.
- `deli supports [on|off|organic|snug|grid] [--angle N] [--buildplate-only|--everywhere]` sets the `support_material*` settings through the same path as `deli set`; `settings.effective(doc, key)` reports a setting's value and whether it comes from the print, a profile or PrusaSlicer's default (`_engine.setting_default`).
- `deli scale [part] [x|y|z] <factor>` and `deli rotate [part] [x|y|z] <degrees>` record a part's `scale` and `rotate` (three numbers each) in its `[[part]]` table; both are absolute, relative to the model file, and the engine applies scale, then rotations about x, y, z. The part must be named when there is more than one.
- `deli move [part] <x> <y>` gives a part a place on the bed, recorded as `at` (the x and y of its middle) in its `[[part]]` table; a part without one is arranged, around those that have one. `deli move [part] z <mm>` records `z`, how far its underside is above the bed: negative sinks it, and what is below the bed is not printed. `deli move [part] plate N` keeps it to plate N (`plate`; its `at` is then on that plate). `deli move [part] auto` drops all three. A part with copies is placed a copy at a time, `deli move [part] --copy N X Y | plate N | auto`, recorded in a `[part.copy.N]` table (`project.copy_place`/`copy_plate`; a part's only copy keeps them in the part, and `project.set_part_count` moves them as copies come and go); `z` is the part's. Moving to X Y first gives every other unplaced copy on that plate the place it has now (`_keep_the_rest` in `cli.py`, from `_engine.mesh`), so a move never moves anything else; the engine refuses placed copies whose convex hulls overlap, and arranges unplaced copies as if nothing were placed, then again only those in a placed one's way. `deli rotate [part] --copy N` gives a copy its own `rotate` in `[part.copy.N]` (`project.copy_turn`; the engine's eighth part field, an instance rotation relative to the part's, each copy dropped onto the bed by itself); rotating the part clears them. `deli arrange` drops every part's places and plates; `--plate N` only the places of copies on plate N, which keep their plate. `deli translate` is an alias of `deli move`.
- `deli pause <layer>...` records the layers the print pauses after as `pause = [...]` at the top of `deli.toml`; `deli pause off [layer...]` removes them. `--plate N` is another plate's, kept as `pause` in a `[plate.N]` table (`project.pauses(doc, plate)`). Layers are counted as the G-code and the viewer's slider count them (supports' own layers included). `slice` hands them to the engine, which writes the printer's `pause_print_gcode` before the following layer. There is no separate colour-change command: a pause is where the filament is changed, and the Centauri's pause G-code is `M600` itself.
- `deli slice [-o FILE|DIR]` merges the chosen printer, filament and process with `[settings]` and slices every part and copy in-process, arranged on the bed by PrusaSlicer's arrange, writing `<part>.gcode` (one part) or `<directory>.gcode` into deli's cache (`<name>-plateN.gcode` per plate when the parts need several: arrange spills what does not fit onto further plates, as PrusaSlicer 2.9 lays out its beds, and a part's `plate` keeps it to one; `_engine.plates` says where each copy goes and `_engine.slice` slices one plate; the folder's `plates` file maps plates to files, `project.fresh_gcode` returns them by plate), `$XDG_CACHE_HOME/deli/gcode/<directory>-<hash>/` (`project.gcode_path`; the user wanted the G-code out of sight), one file per print, and with `-o FILE|DIR` a copy there too. `project.keep_gcode` tidies the cache: folders of print directories that are gone are removed. A printer's unusable bed area is cut out of its `bed_shape` polygon by the Orca converter, and `_engine.cpp` keeps parts off it. When the printer's `thumbnails` setting asks for them, `_engine.cpp` draws a picture of the parts into the G-code with its own small renderer, since libslic3r leaves that to PrusaSlicer's window. When the printer has a `gcode_footer`, `slice` adds it just before the estimated printing time, with `{total_layer_count}` filled in; converted printers have Orca's `; total layers count = N` there, which is where the Centauri Carbon reads the layer count from. It refuses if a chosen profile is missing from the library or its hash no longer matches (`deli <kind> <name>` accepts the new version).
- `~/.config/deli/config.toml` (`src/deli/config.py`, edited with `deli config <key> [value]`, keys `printer` and `printers.<printer>.<host|api_key|filament|process>`) names the default printer (top-level `printer`) and says what each printer is connected to and which filament and process a new print on it starts with. These are defaults only: nothing checks a print's own choices against them. A print being started (the first command in a directory without a `deli.toml`: `add`, `set`, `supports`, `filament`, `process`) takes the default printer and that printer's `filament`/`process`, written into `deli.toml` with their hashes like any other choice (`_config_fills` in `cli.py`); a print that already exists is left alone. `deli printer X` applies the printer's `filament`/`process` defaults to a print that has none; `deli filament` marks the printer's default. The config keeps no list of filaments on hand (the user: deli is not an inventory, and it would always be out of date); an old `filaments` key is ignored and can be removed with `deli config --unset`.
- `deli send [FILE] [--print] [--plate N]` uploads the print's G-code (every plate's; `--print` with several needs `--plate`) (slicing first when it is missing or `deli.toml` or a part's file has changed since: `project.fresh_gcode` compares them with the `made-from` file `slice` writes beside the G-code, not by time, since model files can be dated in the future), or FILE, to the chosen printer's `host` from the config, or `DELI_HOST` (`elegoo://`, `moonraker://` or `octoprint://`; key from the config's `api_key` or `DELI_API_KEY`). `src/deli/send.py` has the Elegoo SDCP protocol, reimplemented from OrcaSlicer, and a minimal websocket client; tests use fake printers only.
- `deli setup` (`_setup` in `cli.py`) sets deli up once: tab completion for `$SHELL` (`complete.completion_file`: bash-completion's per-user folder when the package is installed, fish's completions folder; else a line in `~/.bashrc` or `~/.zshrc`, added only on a yes), then the printer from its hostname or IP alone (the user's aim: setup made smarter by asking the printer). `src/deli/probe.py` asks the address, read-only, what answers: Moonraker on 80 or 7125 (`/printer/info`, and the config file's nozzle, bed, Z travel, kinematics and the parameters `PRINT_START` reads), an Elegoo printer's SDCP discovery (`M99999` on UDP 3000, three tries, then the websocket's attributes, since the Centauri's Wi-Fi drops UDP), OctoPrint's page, and Bambu's ports (recognised, not sent to). `_pick_for` turns that into Orca's printer: by model (Elegoo), else `Presets.fitting_printers` (nozzle from the name, bed within 10 mm, `printer_structure`), a close name match to the hostname first and the rest alphabetically, with a note when a model like the hostname exists only with other nozzles; without an address `_pick_printer` (model, then `_pick_nozzle`). `_fit_to` lowers `max_print_height` to the Z travel and adds `MATERIAL=[filament_type]` to `PRINT_START` when the macro reads it, and `SET_PRINT_STATS_INFO` (layer count and current layer, for Mainsail and Fluidd) to the start and layer-change G-code of a Klipper printer without it (`_layer_info`), on a printer imported in that run only (`library.update`). The default printer is set only when there is none, else on a yes. Two steps, a ✓ summary with Orca's names; the one command with colour (`_styled`: only on a terminal, never with `NO_COLOR` or `TERM=dumb`). It never writes a `deli.toml`. Names match by `orca_install.matches`: the typed text, or every typed word in any order.
- `deli completion bash|zsh|fish` prints a completion script; bash and zsh call the hidden `deli __complete --line LINE --breaks CHARS` with the line up to the cursor as typed, which deli splits itself (bash splits at `@`, and Orca's names have it and spaces) and answers escaped and cut to what bash replaces; fish calls `deli __complete INDEX WORDS...`. `src/deli/complete.py` answers from the parser, the library, the print, the config and Orca's cached presets.
- `deli view` serves a single viewer page, one plate at a time with a button per plate (`/state`'s `plates`, `?plate=N` on `/mesh` and `/toolpaths`), (`src/deli/view.py`, `src/deli/viewer/`: three.js vendored, MIT) on localhost showing the part on the bed, placed as `slice` places it, and, while the G-code `deli slice` wrote is still the print's (`project.fresh_gcode`), in the same view: every extrusion, supports included, coloured by what it is for, or by speed, flow or layer time ("Colour by"), with a slider to cut through the layers and a box to show only the slider's layer (a clipping plane) (`/toolpaths`, read from the file by `_engine.toolpaths` with PrusaSlicer's G-code reader, which also gives each move's speed and flow and the estimated time per role and per layer); the colours turn lighter between one pause and the next. The legend lists each role's time; clicking one hides or shows it (a bit per role in the vertex shader; travel starts hidden). The model is drawn faint over current G-code, or hidden; it is a Model row in the legend, shown by itself (the G-code hidden, since it is where the parts were) when there is no current G-code or a part is being dragged, Lay flat or Overhangs is in use (Lay flat put down once its command is applied or its panel closed, any tool by Esc), the user's click holding until the G-code is sliced again or goes out of date (`/state`'s `sliced`, the G-code's mtime; `stale` when it is out of date, which the page says). The one slider is the layers, cutting the model at the layer's height (a clipping plane), or with no G-code a height to cut the model at (the inside drawn dark from its back faces). The Overhangs button draws in red the downward faces flatter than the angle supports go by (`/state`'s `overhang`: `support_material_threshold`, or for 0 PrusaSlicer's automatic slope, half an external perimeter's width per layer). Dragging a part (left button, no tool; one copy: `/mesh` says which triangles are each copy's; off the bed or onto another copy's hull offers nothing) and Lay flat (click a face; the copy's own rotation, `/state`'s `turns`) write the `deli move` or `deli rotate` that would do it, Supports (`deli supports on|off`, from `/state`'s `supports`), Arrange (once something was moved) `deli arrange`, `--plate N` for the plate shown when there are several, and Pause here the `deli pause` for the slider's layer, in a panel with Apply, which POSTs it to `/run` (only `move`, `rotate`, `pause`, `arrange`, `supports`; run in-process with `cli.main`, output captured), and Copy (`/mesh` says which vertices and triangles are each part's; lay flat takes the face's direction back to the file's and finds new x and y angles, keeping z). The Measure button (or M) labels the distance between two clicked points on the part (snapped to a nearby triangle corner) or the toolpaths, and along each axis, in mm or inches, as is every length the page shows (the switch below the print's description; the page's localStorage; lengths carry `data-mm` and are rewritten in place; speeds, flows and commands stay metric); the line follows the pointer between the clicks; a right-click clears it and turns measuring off. It changes a print only by running those commands (DESIGN.md); `/run` needs the page's own Host and Origin and the token `deli view` puts in the address (`?t=`; generated by `view.start`, handed to the background process in its environment, kept in its 0600 record); Slice (shown when the G-code is missing or out of date) POSTs `/slice`, which runs `deli slice` in a subprocess (`view.Slicing`; one at a time) whose progress and output `/state` reports as `slicing`; Send and Print (once sliced, when `send.host_for` finds the printer's address: `/state`'s `host`) POST `/send` with only `plate` and `print` (`view.send_args`, never a file), which runs `deli send` the same way (`view.Job`, reported as `sending`), Print's Apply reading Start printing; printer setup and choosing profiles stay in the shell. It follows `deli.toml` and the G-code by polling `/state`. `deli view` returns at once: the page is served by a detached background process, found again by a later `deli view`, which stops ten minutes after the page is closed or with `deli view --stop`.
- Parts cannot yet have settings of their own; `[settings]` applies to the whole print.

## Engine

- Source: `vendor/PrusaSlicer`, a shallow git submodule pinned to tag `version_2.9.6`.
- `libslic3r` is a static library target in `vendor/PrusaSlicer/src/libslic3r`. PrusaSlicer's dependencies are built by its own superbuild in `vendor/PrusaSlicer/deps` (packages can be skipped with `PrusaSlicer_deps_PACKAGE_EXCLUDES`).
- The binding is `deli._engine` (`src/deli/_engine.cpp`, nanobind), built by the root `CMakeLists.txt` through `scikit-build-core` when `uv sync` runs. It needs PrusaSlicer's dependencies in `build/deps` (gitignored); the first build takes about 16 minutes, later ones seconds.
- `build/prusaslicer/src/prusa-slicer` is a console build of the same engine, for checking results.
- `PLAN.md` has the build commands, the current state and the next steps; read it before working on the engine.

## Commands

```
uv run deli          # run the CLI
uv run pytest -q     # run the tests
make install         # put `deli` on the PATH, pointing at this checkout
make reinstall       # the same, rebuilding the binding after C++ changes
make uninstall
make wheel           # build dist/deli-*.whl to give to someone
```

Releasing: set `version` in `pyproject.toml`, commit, and push a tag `vX.Y.Z` with the same version. `.github/workflows/wheels.yml` refuses a tag that does not match, builds and tests every platform's wheel, and publishes them as a GitHub release (a tag with a `-`, such as `v0.2.0-rc1`, as a pre-release). `install.sh` (the README's `curl ... | sh`) installs the latest non-pre-release's wheel for the machine with uv, so a release needs nothing changed there; a new platform needs a case in its `platform`. Each platform's build job uploads its wheel as an artifact named `wheel-<platform>`; a new platform's test job goes in the release job's `needs`.

## Local environment

- GCC 15.2 and CMake 4.2, both newer than PrusaSlicer's pinned dependencies expect. `sudo` needs a password.
- No system zlib or libpng dev packages; both are built into `build/deps/destdir/usr/local`.
- Orca profiles to convert from:
  - bundled: `/var/lib/flatpak/app/com.orcaslicer.OrcaSlicer/current/active/files/share/OrcaSlicer/profiles`
  - user presets: `~/.var/app/com.orcaslicer.OrcaSlicer/config/OrcaSlicer/user/default`

## Conventions

- `DESIGN.md` holds the principles the commands follow (shell-native; a print is a text file of only what changed; defaults never constrain; users need not know where a profile lives; one way to do each thing, a noun command lists without a name and chooses with one, the main object an argument not a flag; nothing changes under a print; quiet by default; build products out of sight; no surprises; network only where needed; honest about what is checked). Check a change against it, and update it when a principle changes.
- `CONTRIBUTING.md` has the contributor workflow; `CHANGELOG.md` has an Unreleased section to update with each user-visible change, marking changed behaviour **Changed**.
- Tests never use the network (`tests/conftest.py`); printers and OrcaSlicer's GitHub are faked.
